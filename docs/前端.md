# 前端工作总结

本文档记录 `frontUI` 分支当前完成的桌面前端工作。

## 定位

本分支要做的是“能打开的软件前端”，不是浏览器网页前端。因此当前前端工程采用 Electron + Vite + React + TypeScript，启动后会打开独立桌面窗口，窗口标题为 `Agent_bio_react`。

前端代码统一放在：

```text
desktop_app/
```

该目录独立于 Python Agent 主逻辑，后续可以通过 API 或本地 IPC 接入任务运行、截图流、日志流和模型配置。

## 当前目录结构


`.gitignore` 已忽略：

```text

```

## 启动方式

首次运行：

```powershell
cd F:\Agent_bio_react\desktop_app
npm install
npm run start:desktop
```

日常打开：

```powershell
cd F:\Agent_bio_react\desktop_app
npm run start:desktop
```

`start:desktop` 会先执行构建，再启动 Electron：

```json
"start:desktop": "npm run build && node scripts/start-electron.cjs"
```

## 已实现界面

当前版本是桌面软件原型，已实现：

- 顶部标题：`Agent_bio_react`。
- 顶部导航：任务、运行监控、设置、日志。
- 首页左侧任务列表：
  - 支持勾选任务。
  - 展示任务状态。
  - 提供开始运行、停止按钮。
- 首页右侧当前任务窗口：
  - 模拟展示 Thermo BioPharma Finder 5.1 当前窗口。
  - 展示任务步骤、当前执行状态、推理模型、视觉模型。
- 运行监控页：
  - 展示运行事件流。
  - 展示当前任务窗口预览。
- 设置页：
  - 支持切换推理模型。
  - 支持切换视觉模型。
  - 内置推理模型示例：DeepSeek、Manual、Scripted。
  - 内置视觉模型示例：Qwen、Temporary。
  - 支持自定义模型配置，包括 API Key、Endpoint、Model、Timeout、Max Tokens。
- 日志页：
  - 按当前控制台日志规范展示时间戳之间的分隔线样式。

UI 风格参考了用户提供的 MAA 截图：白底、细边框、顶部 Tab、左侧菜单、紧凑表单、低装饰密度。

## 关键技术决策

### 使用 Electron

用户明确要求“能打开的软件前端，不是网页前端”，因此不再以浏览器访问 Vite dev server 作为交付形态，而是使用 Electron 打开桌面窗口。

Electron 主进程文件：

```text
desktop_app/electron/main.cjs
```

窗口加载的是本地构建产物：

```js
mainWindow.loadFile(path.join(__dirname, "..", "dist", "index.html"));
```

### 使用相对资源路径

第一次打开 Electron 窗口时出现空白页。原因是 Vite 默认构建出的资源路径是：

```html
src="/assets/..."
href="/assets/..."
```

Electron 使用 `file://` 加载本地文件时，绝对路径会导致 JS/CSS 资源找不到。已在 `vite.config.ts` 中设置：

```ts
base: "./"
```

修复后构建产物变为：

```html
src="./assets/..."
href="./assets/..."
```

Electron 窗口可以正常渲染。

### 清理 ELECTRON_RUN_AS_NODE

当前运行环境中存在：

```text
ELECTRON_RUN_AS_NODE=1
```

这会导致 Electron 以 Node 模式启动，`require("electron").app` 为 undefined，无法创建窗口。已新增启动脚本：

```text
desktop_app/scripts/start-electron.cjs
```

该脚本启动 Electron 前会删除该环境变量：

```js
delete env.ELECTRON_RUN_AS_NODE;
```

## 当前边界

当前桌面前端仍是原型层：

- 任务列表使用前端模拟数据，还未从 `tasks/` 动态读取。
- 当前窗口是 UI 模拟预览，还未接入真实截图流。
- 开始运行、停止按钮还未调用 Python Agent。
- 模型配置表单还未写入后端配置或环境变量。
- 日志页还未接入真实日志文件流。
- 还未打包成 `.exe` 安装包，目前通过 `npm run start:desktop` 启动。

## 后续建议

下一步建议按以下顺序推进：

1. 在 Python 侧提供本地 API 或 IPC 服务，暴露任务列表、运行状态、截图路径、日志流和模型配置读写。
2. 在 `desktop_app/src/` 下新增 `api/` 层，统一封装前端到 Python 后端的调用。
3. 将任务列表从模拟数据替换为真实 `tasks/` 解析结果。
4. 将当前任务窗口从模拟 UI 替换为实时截图或截图流。
5. 将模型配置表单接入 DeepSeek、Qwen 等现有 provider 的配置来源。
6. 增加打包流程，生成可直接双击运行的 Windows 桌面程序。
